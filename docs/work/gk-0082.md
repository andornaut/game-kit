## Criteria

- Separate browser or worker cache behavior from origin or deployment visibility.
- Prove a shared failure and recovery in a controlled Chromium run of the existing router.
- If the shared path contributes to the failure, fix it while preserving build identity, saves,
  cached valid manifests and the existing update offer.

## Outcome

In the Chromium fixture, the old controller replayed a cacheable manifest 404 after the server
had published that URL. The normal retry now reloads the same URL after 404. The validated 200
can populate the HTTP cache. Both cacheable and unstored 404 fixtures recover without switching
the active build or changing the save. The production failure's cache provenance remains unknown.
