## Criteria

- A refused state on `createButton`: the button stays focusable and in the
  Tab order, and Enter, Space and pointer presses deliver a refusal through
  the caller's refusal cue, as the pager callback does.
- It adds no spoken description, and exposes a stable attribute the game can
  style. The kit no longer strips the game's refused marking on refresh.
- Existing states, including pointer refusal and unavailable, are unchanged.

## Outcome

Published in [GameKit 0.87.0](https://github.com/andornaut/game-kit/releases/tag/v0.87.0).
Consumer adoption follows each game's normal delivery.

Additive. A caller that never returns the refused state sees no change.

- `runtime/web/ui/dom/button` `ButtonState.availability` takes `{ kind: "refused" }`. The button
  stays enabled, focusable and in the Tab order, sets no `aria-description` or reason, and is
  `aria-disabled="true"` on every refresh while refused.
- `ButtonOptions.refusal` is a `ButtonRefusal`: `{ cue, reducedMotion }` plays the kit cue,
  leaving one already playing to finish, or `{ refuse, reducedMotion }` calls the game's
  `refuse(reducedMotion, control)` with the refused button. Enter, Space, pointer presses and
  holds under a current action play it; without it a refused press does nothing.
  `refuseButton(refusal, control)` plays a refusal the same way, and `PagerRefusal` is now this
  type, with the pager's behaviour unchanged.
- Styling: `aria-disabled="true"`, the attribute pointer refusal and unavailable already set and
  the kit stylesheets draw as disabled. No new attribute.
- Form rows and HUD discs pass the state and option through to `createButton`.
- Tests pin each existing state's markup, hold action and dispatches as 0.86.1 rendered them.
