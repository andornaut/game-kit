## Criteria

- The loading failure and capability error panel takes a panel highlight
  token, so a game can draw its bevel row without editing the inline shadow.
- The crash screen's error details summary shows focus as a fill, not an
  outline, matching the cross-game fill-only focus rule. Forced colours keep a
  visible system focus.
- Unset tokens keep today's look, except the summary focus change.

## Outcome

Additive, apart from the summary focus fill, a visible change for every game.
Consumer adoption follows each game's normal delivery.

- Panel highlight: `LoadingFailurePresentation` takes optional
  `panel.highlightHeightPx` with `palette.panelHighlight`, a hex colour. Given
  together, the panel's inline shadow starts with
  `inset 0 <height>px 0 <colour>`, the bevel row under the top border, above
  the lip and drop shadow. One without the other, a negative or non-finite
  height or a non-hex colour throws before any DOM change. Omitted, the shadow
  is unchanged. It reaches the `prepareBrowserLaunch` capability error through
  the same presentation, and `setPresentation` adds or removes it. Archie can
  pass its paper bevel here and drop `paintPaperBevel`.
- Crash details summary: focus was a 3 px double outline in the crash button
  face, 2 px offset, and a 2 px `Highlight` outline in forced colours. It is
  now a fill with no outline: `buttonFocusFace` and `buttonFocusText`, else the
  row's own text colour (`textPrimary`, else `CrashColours.text`) as the fill
  and its backdrop (`cardFace`, else `CrashColours.background`) as the text.
  Forced colours fill `Highlight` with `HighlightText`. Geometry is unchanged.
  Archie can drop its summary override.
- Games without uiTheme see no other change.
