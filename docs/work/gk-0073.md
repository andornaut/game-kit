## Criteria

- ESLint refuses an import whose specifiers are all inline `type`, which
  under verbatimModuleSyntax still loads its module and hides a runtime edge
  from `import-x/no-cycle`. Such imports are written as `import type`.
- A lint test proves the rule fires on that form and not on `import type` or
  a mixed import.

## Outcome

`@typescript-eslint/no-import-type-side-effects` runs with `import-x/no-cycle`
over source, scripts and tests. The kit had no such imports, so no source
changed. `scripts/lint-security.test.ts` covers the three forms. Tooling only;
the published package is unchanged.
