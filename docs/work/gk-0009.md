## Scope

In a later minor release, the precache plugin can concatenate small files into packs of about 1 to 2 MB with an index, and the installer splits them into per-URL entries, verifying each member, so runtime URLs are unchanged. Design: [Install and update design](../design/install-and-update.md).

## Criteria

- An install of a packed build makes far fewer requests with identical cached entries.
- Updates fetch changed members singly when few, else changed packs.
- Pack sizes are set after Art's sheet measurement.

## Decisions

- Decisions (user, 2026-11-18): page installer with a router-only worker; defects 9 and 10 patched in 0.58.2 with a switch stopgap that skips re-hashing install-verified entries; asset groups removed in 0.59.0; kit packs plus Art sheets in 0.60.0; update discovery by a page fetch of `build.json`; Update now is game-rendered, the kit firing `onUpdateReady`; Archie boot loads every group behind the one loader once installed.

- The renderer shipped first in 0.60.0. The initial plan put packs in the following minor release. [Decision](gk-0026.md#decisions).
- D1 (user, 2026-11-22; answers gk-next-minor-order): Ship the ready APIs first (Recommended)

## Outcome

GameKit 0.63.0 adds opt-in gzip packs with per-member size and SHA-256
verification. Verified entries survive retry. Sparse updates and invalid or
unavailable packs use the original individual URLs.

On loopback, 1,225 retained Ada boot SVGs from source `8753c4af` took 426,820
body bytes with individual Brotli-5. A single emitted pack with a 2 MiB decoded
limit took 135,377 body bytes and added 2,347 Brotli-5 bytes to the manifest,
for 137,724 incremental bytes. All decoded bodies matched. This qualifies the
sample under those transfer settings. Games choose opt-in after qualifying
their own delivery route.
