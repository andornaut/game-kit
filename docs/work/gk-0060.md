## Criteria

- Map every `src/` area onto the gc-0029 bands and record the map in the
  packaging design.
- ESLint enforces downward-only imports between bands, single public entries
  per area, and the existing engine and environment import rules.
- During the migration, one temporary import check places every module in a
  band and fails on a cycle, a wrong-direction import or an unplaced module not
  in its known-violations table, which only shrinks. It replaces
  `scripts/import-cycles.test.ts`.
- Fix the violations, then remove the check. Public export paths and data
  contracts stay unchanged.
- Policy: game-coordinator gc-0029, source structure.

## Outcome

- The packaging design maps every `src/` area onto the gc-0029 bands, with
  ordered layers inside each band. The kit has no page entries, so no Entries
  band. An area may import its own layer or an earlier one, as in Coordination
  Kit, so type-only imports may form a cycle only within a layer.
- Each directory area that another area imports has an `index.ts` entry that
  re-exports what other areas use, and every cross-area import goes through it.
- Build-time code lives in `src/build/`, pure at its top and Node and Vite in
  `build/vite/`. The build label moved to `web/buildLabel`, `mapLimit` to the
  foundation helpers, the build archive codec (which needs `TextEncoder`) to
  `web/pwa/archive/`, `uiGlyphPen` beside the `view/phaser` command list, and
  the press guard types from `web/ui/dom/domPress` to `input/pressGuard`,
  which ended the `web/input/dom` and `web/ui/dom` type cycle.
- `scripts/source-bands.test.ts` replaced `scripts/import-cycles.test.ts`
  during the migration. Its known-violations table shrank from 123 entries to
  none, and it is removed.
- ESLint guards the bands: `import-x/no-restricted-paths` zones built from
  `SOURCE_BANDS` reject an import into a later layer, past another directory
  area's entry, or into `scripts/` or `tests/`, type-only imports and
  re-exports included, and the config refuses to load while a shipped module is
  in no area or in two. The environment rules and `import-x/no-cycle` are
  unchanged. `eslint-plugin-import-x` is locked at 4.18.1, and its resolver maps
  a `.js` specifier to its `.ts` source. `scripts/lint-security.test.ts` runs the
  real config through ESLint's Node API: a runtime cycle named by `.ts` or `.js`
  specifiers fails `import-x/no-cycle`, and a type import up a band fails the
  layer rule.
- Public export paths and data contracts are unchanged. The `build/` and
  `runtime/web/buildLabel` exports point at the moved files, and
  `runtime/web/ui/dom/domPress` still exports `PressGate` and `PressGuard`.
