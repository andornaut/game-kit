## Criteria

- A grouped install or staging whose device sound format changes between
  sessions recovers on the next launch, as the ordinary install path does,
  instead of failing until the next deploy.
- Press-area clamping measures each member's layout position, so a refusal
  shake that is playing does not shift the clamp.

## Outcome

Published in [GameKit 0.86.1](https://github.com/andornaut/game-kit/releases/tag/v0.86.1).

Internal fixes with no API change. Consumer adoption follows each game's normal delivery.

- Grouped format change: the group store's marker for a build holds the pointer reduced to the
  sound format it was sealed for, and `reuse`, `put` and `seal` refused any other pointer for
  that version, so a half-installed or staged build failed until the next deploy once the
  device's format changed. A marker for the same build with the same groups without a format,
  but other format groups, is now sealed for another format: `reuse` and `put` store beside it,
  reusing shared groups by digest, and `seal` replaces it in one record write under the
  build-state lock. Until then the build serves the format it was sealed for, and a router
  snapshot keeps its files. The other format's groups stay until the build is reclaimed.
  Activation, staging publication and the router still require the device format's marker, so
  pins, single activation and save fences are unchanged. Any other marker still conflicts.
- Press context: `apply()` measured members with `getBoundingClientRect`, which includes a
  playing refusal shake's `translate`. It now measures each member's layout position: the box
  as drawn less the computed CSS `translate` of the member and of each ancestor below the root
  (a percentage of the element's layout box). Projected members are unchanged.
