## Criteria

- An optional game projection for the DOM action group, form rows and
  slider, so every placed part lands on whole device pixels through the game's
  grid, as the projected page frame does.
- A projected page frame can use the kit footer action group.
- Without a projection, layout and CSS stay byte-identical.

## Outcome

Published in [GameKit 0.84.0](https://github.com/andornaut/game-kit/releases/tag/v0.84.0).
Consumer adoption follows each game's normal delivery.

Every addition is opt-in. Without a projection the markup, inline styles and resolved CSS are
those of GameKit 0.83.0, which `unprojected.test.ts` asserts by digest: of the markup an
action group, a grid, a press context, form rows, a slider and a modal frame with a kit footer
write, and of each stylesheet with its projected rules removed and its length variable replaced
by the unprojected definition.

- `runtime/web/ui/dom/actionGroup`: `arrange` and `arrangeGrid` take `project` with `origin`, the
  group's corner in units. The group takes `data-ui-action-projected` and writes its box, faces,
  middle slot and press outsets in whole CSS px from its projected corner
  (`--ui-action-length: 1px`). A press context with projected groups measures nothing: its
  members are in the projection's space, a placed form row at its placed box.
- `runtime/ui/formRow`: `formRowsGeometry(layout, context)` places a list's rows, icon slot, icon,
  label and value columns, value stack, switch and slider lane in units or through `project`.
  It needs `value.track`; `value.height` sizes a centred switch stack and `SliderLayout.line` a
  slider's first line, since a placed list measures nothing.
- `runtime/web/ui/dom/formRow`: `place({ project, width, origin }, rows)` writes the list as
  explicit CSS px tracks between projected edges, the padding, icon slot sides and column gaps as
  tracks of their own and each row track its pitch to the next, so the subgrid still shares the
  columns. Each row's lengths are written on it in CSS px (`--ui-form-length: 1px`). It returns
  the projected layout and `units`.
- `runtime/web/ui/dom/slider`: a placed slider writes its lane, track, caps, fill and thumb in
  CSS px, the thumb and fill at each step, its cap slices in art pixels, and maps presses through
  the track as drawn.
- `runtime/web/ui/dom/modalFrame`: a projected frame arranges the kit footer with its own
  projection from the footer room's corner, so a projected page can use the footer action group.
- Archie's Settings list and the Pet shop page's Back are proved on Archie's device art-pixel
  grid at four scale and DPR pairs, in the pure geometry and in the DOM writes.
