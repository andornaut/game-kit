## Criteria

- Organize source by cohesive module boundaries, with clean interfaces and
  no import cycles. Keep internals private behind each module's public entry.
- Prefer pure functions; isolate effects (DOM, storage, network, clock, Node
  I/O) at the edges and inject them before the subject.
- Remove duplication, dead code and needless indirection.
- Align layouts, naming, configuration and test placement with Art Kit,
  Coordination Kit and Delivery Kit where they share a pattern.
- Keep the public `runtime/`, `build/` and `test/` exports and installed-build
  data contracts unchanged, or document each change as a release note.

## Outcome

- Imports have no cycles, type-only edges included: the traversal kernel owns the types it
  steps, and `scripts/import-cycles.test.ts` rejects any cycle in `src/`, `scripts/` and
  `tests/e2e/`.
- `launchRules` and `routerRules` hold the pure decisions of the page launch and the router
  worker. One bounded mapper (`src/web/mapLimit.ts`) and one SHA-256 helper replace private
  copies, and helpers that only their own module uses are private.
- Lint, type and test configuration follows the other kits: tests use the tooling lint rules,
  source rejects dynamic imports, `npm run lint` runs named parts, Vitest sets its worker limit
  and TypeScript accepts only erasable syntax.
- Public exports and installed-build data contracts are unchanged. The `src/` layout keeps its
  environment directories, which carry the browser, Phaser and Vite boundaries.
