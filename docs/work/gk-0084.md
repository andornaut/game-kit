## Criteria

- Read the deployment pointer early on valid installed boot without blocking Start.
- Report update preparation before measured bytes and preserve existing callers.
- Carry the explicit update's progress through one reload and the first boot.
- Preserve save, identity, verification, activation, retry and other-tab fences.
- Measure a same-profile grouped update from launch through ready.

## Outcome

[GameKit 0.93.0](https://github.com/andornaut/game-kit/releases/tag/v0.93.0) ships the bounded
pointer read and optional `onUpdateProgress` contract. The exact release commit is
`cf9e7b9a877306c4e194a91ad2c6e556d92eddbf`. The archive SHA-256 is
`a9d000d6e10acecf343c552bce616e209c9ba495aa870616199404c181324899`.

The same-profile grouped [main CI run](https://github.com/andornaut/game-kit/actions/runs/45904949668)
observed a 74.4 ms pointer read start, 391.5 ms preparation frame, 758.1 ms transfer frame and
1,856.8 ms offer. Apply reached navigation in 1,507.8 ms and boot ready in 1,535.4 ms, including
the fixture's 1,500 ms save. These are fixture measurements. The pinned Archie, Chibi and Ada
consumer proofs passed, and the public artifact matched the local and CI assets.
