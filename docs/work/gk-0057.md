## Criteria

- Remove the deprecated `browserLaunchContext` export and every README
  reference, with a release note. `prepareBrowserLaunch` stays the production
  entry.
- Add Makefile `lint`, `test` and `build` targets in the shape of the other
  kits, each running its existing container task.
- Move the grouped install and staging out of `createLaunch` into their own
  module with identical behaviour.

## Outcome

- `runtime/web/pwa/dom/launch` no longer exports `browserLaunchContext`.
  `prepareBrowserLaunch` is the only browser entry; the README migration
  section for 0.78.0 and the consumer proof use it.
- `make lint`, `make test` and `make build` pass their part to the local check
  runner, which installs dependencies and runs that part's container task.
  `make check` is unchanged.
- `dom/launchGroups` holds the grouped first install and grouped staging
  (`installGrouped`, `stageGroups`, `prepareGroups`, `verifyGroupedManifest`)
  over an injected context. `LaunchError` moved to `launchRules`.
  `createLaunch`'s behaviour, log messages and remaining exports are unchanged.
  Its grouped tests stay in `launch.test.ts`, and `launchGroups.test.ts` tests
  the module directly.
